# Формат уровня

Уровень — один JSON-файл в этой папке. Имя файла = `id` уровня плюс `.json`:
`01.json`, `02.json` и так далее. Файлы правятся руками в любом редакторе,
код их не генерирует.

Чтобы добавить уровень: скопируй `01.json`, поменяй `id`, `title` и карту.
Ничего регистрировать больше не нужно — уровень грузится по своему `id`.

## Поля верхнего уровня

| Поле | Тип | Обяз. | Что значит |
|---|---|---|---|
| `id` | строка | да | Совпадает с именем файла без расширения: `"01"` |
| `title` | строка | да | Человеческое название, видно в меню (Этап 5) |
| `tileSize` | число | да | Размер тайла в пикселях. Сейчас везде `32` |
| `spawn` | `[колонка, строка]` | да | Где появляется игрок в начале уровня |
| `lives` | число | нет | Жизней на уровень, по умолчанию 3 |
| `legend` | объект | да | Символ карты → имя тайла (см. ниже) |
| `map` | массив строк | да | Сама карта. Все строки одной длины |
| `chests` | массив | нет | Сундуки с задачами |
| `doors` | массив | нет | Двери |
| `platforms` | массив | нет | Движущиеся платформы |
| `hazards` | массив | нет | Кометы — движущиеся шипы |
| `cannons` | массив | нет | Пушки — стреляют снарядами вбок |

## Карта

`map` — массив строк одинаковой длины. Один символ = один тайл. Первая строка —
верх уровня, последняя — низ. Символы расшифровываются через `legend`.

Понимаемые имена тайлов:

| Имя | Символ по традиции | Поведение |
|---|---|---|
| `ground` | `#` | Твёрдый. Земля и стены |
| `platform` | `=` | Твёрдый. Отличается только видом |
| `spring` | `S` | Твёрдый. Упал сверху — высоко подбрасывает (выше обычного прыжка) |
| `spike` | `^` | Не твёрдый. Касание — минус жизнь и возврат на чекпоинт |
| `coin` | `o` | Не твёрдый. Собирается при касании |
| `chest` | `C` | Не твёрдый. Открывается по `E` вплотную |
| `door` | `D` | Не твёрдый. Выход с уровня, рисуется на два тайла вверх |
| `checkpoint` | `F` | Не твёрдый. Точка возврата после смерти |
| `empty` | `.` | Пусто |

Символы можно назначать любые — важно только имя справа от двоеточия в
`legend`. Символ, которого нет в легенде, считается пустотой.

Края карты слева и справа — невидимые стены. Ниже последней строки пусто:
туда можно упасть, это стоит жизни и возвращает на чекпоинт.

## Сундуки

```json
{ "at": [32, 15], "subject": "algebra", "grade": 5, "difficulty": 1, "keyColor": "amber" }
```

| Поле | Что значит |
|---|---|
| `at` | `[колонка, строка]`. Должно совпадать с тайлом `chest` на карте |
| `subject` | `"algebra"`, `"geometry"` или `"physics"` — из какого раздела задача |
| `grade` | Класс, на который рассчитана задача: 5, 6 или 7 |
| `difficulty` | Сложность 1–3 |
| `keyColor` | Цвет ключа, который выдаст сундук |

Поля `subject`, `grade` и `difficulty` пока никем не читаются: движок задач
появится на Этапе 4, до этого сундук выдаёт ключ сразу.

## Двери

```json
{ "at": [44, 15], "keyColor": "amber", "exit": true }
```

| Поле | Что значит |
|---|---|
| `at` | Нижний тайл двери, он же тайл `door` на карте. Рисуется дверь на два тайла вверх |
| `keyColor` | Каким ключом открывается |
| `exit` | `true` — эта дверь заканчивает уровень. `false` или пропущено — просто ворота на пути |

**Запертая дверь твёрдая** — сквозь неё не пройти и её не перепрыгнуть, если
сверху есть потолок. Поэтому ворота посреди уровня работают: без нужного ключа
дальше не пускают. Открывшись, дверь перестаёт быть препятствием.

Ставя ворота, закрой колонку над ними тайлами `ground` до самого верха карты —
иначе игрок просто перепрыгнет дверь: прыжок берёт два с половиной тайла, а
дверь высотой в два.

Хотя бы одна дверь на уровне обязана быть `"exit": true`, иначе уровень нечем
закончить — загрузка остановится с ошибкой. Ключ, который не выдаёт ни один
сундук, тоже считается ошибкой.

Цветов ключей сейчас три: `amber`, `teal`, `coral`. Хочешь новый — добавь его в
`KEY_COLORS` в `src/game/entities.js`, иначе ключ будет нарисован серым.

## Движущиеся платформы

```json
{ "from": [21, 15], "to": [26, 15], "tiles": 2, "speed": 55 }
```

| Поле | Что значит |
|---|---|
| `from` | Начальная позиция, `[колонка, строка]` |
| `to` | Конечная позиция. Платформа ходит между ними туда-обратно |
| `tiles` | Ширина платформы в тайлах (высота всегда полтайла) |
| `speed` | Скорость в пикселях в секунду. 40–80 — удобно для игрока |

Платформа твёрдая со всех сторон, игрок едет на ней вместе с грузом. Диагональ
работает: `from` и `to` могут отличаться и по колонке, и по строке.

## Батут (`spring`)

Обычный твёрдый тайл на карте — рисуется буквой `S` (или любой, назначенной на
`spring` в `legend`). Упал на него сверху — подбрасывает высоко вверх, заметно
выше обычного прыжка (≈3.7 тайла против 2.5). Высота фиксированная. Сбоку и снизу
это просто стена. **Спавн на батут не ставь** — игрок будет бесконечно скакать и
не «устоится».

## Кометы (`hazards`)

Движущиеся шипы. Убивают касанием, как обычный шип, но не твёрдые — сквозь них
нельзя пройти живым, а не «нельзя пройти».

```json
{ "from": [10, 3], "to": [10, 12], "speed": 90 }
{ "from": [14, 0], "to": [14, 15], "speed": 150, "mode": "fall", "phase": 0.5 }
```

| Поле | Что значит |
|---|---|
| `from` | Начало траектории, `[колонка, строка]` |
| `to` | Конец траектории |
| `speed` | Скорость в пикселях в секунду. 80–200 — рабочий диапазон |
| `mode` | `"patrol"` (по умолчанию) — туда-обратно. `"fall"` — падает из `from` в `to` и мгновенно возвращается в начало |
| `phase` | Только для `fall`: `0…1`, сдвигает старт вдоль траектории. Несколько комет с разными `phase` = дождь вразнобой |

«Дождь с неба» — это несколько `fall`-комет в соседних колонках с разными
`phase`. Аудит проверяет их честно: он не поведёт игрока сквозь комету, а ищет
окно между пролётами. Если аудит говорит «проходится» — окно есть.

## Пушки (`cannons`)

Стоят на месте и раз в `interval` секунд выпускают снаряд вбок. Снаряд летит по
прямой с постоянной скоростью, убивает касанием (как шип) и исчезает за краем
уровня. Сама пушка не твёрдая — сквозь неё можно пройти.

```json
{ "at": [26, 12], "dir": -1, "speed": 130, "interval": 1.9, "phase": 0, "kind": "ball" }
```

| Поле | Что значит |
|---|---|
| `at` | `[колонка, строка]` — где стоит пушка и откуда вылетает снаряд |
| `dir` | `-1` — стреляет влево, `1` — вправо |
| `speed` | Скорость снаряда, пикс/с. 90–150 — рабочий диапазон |
| `interval` | Секунды между выстрелами |
| `phase` | `0…1` — задержка первого выстрела в долях интервала: `0` — сразу, `0.5` — через полцикла. Разные `phase` у нескольких пушек = стрельба вразнобой |
| `kind` | `"ball"` (мяч, по умолчанию) или `"bullet"` (пуля) — только внешний вид |

Снаряды летят на высоте пушки. Ставь пушку на строку выше пола (там, где идёт
игрок), чтобы снаряд шёл по телу и его надо было перепрыгивать. Аудит пушки не
знает и снаряды игнорирует — поэтому не перегораживай ими единственный проход
без зазора: между выстрелами всегда должно быть окно, чтобы проскочить.

## Проверка после правки

Открой **`scripts/audit-levels.html`** — аудит проходит каждый уровень из
`index.json` и проверяет:

- расстановку: сущности не внутри стен, платформа в точке покоя не налезает на пол;
- проходимость: от спавна реально дойти до каждого сундука и до двери-выхода,
  собирая ключи по дороге;
- капканы: нет площадки, с которой нельзя ни уйти, ни упасть.

Он обходит уровень честной симуляцией — теми же прыжками, что доступны игроку.
Если аудит говорит «проходится», значит проходится.

Отдельный уровень открывается по ссылке `?level=03`. Опечатка в JSON не проходит
молча: загрузка остановится и скажет, что именно не так.
